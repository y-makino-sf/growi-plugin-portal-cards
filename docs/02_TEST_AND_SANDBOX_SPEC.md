# テストおよびローカル動作確認（Sandbox）仕様書

## 1. Vitest による自動テスト（`npm test`）
`test/plugin.spec.ts` で以下の7項目を検証すること。
1. **`package.json` 検証**: `name` が `"growi-plugin-portal-cards"` かつ `growiPlugin.schemaVersion` が `"4"` であること。
2. **DSLパーサー＆AST変換検証**: ```` ```portal(cols=2, shortcuts=4) ```` 内のパイプ区切り行・コメント行・個別オプション（`color`, `pins` 等）が正しくパースされ、`<growi-portal-cards>` の属性に変換されること。
3. **自ページ除外と件数カウント検証**: 起点自身を除外し、参照確認後に実際に表示するカード数を「表示N件」と表示すること。候補総数を含めない。
4. **人気順（`sort=popular`）ページカード抽出検証**: 人気スコア（いいね×2＋閲覧者数）の降順で上位N件をカード表示すること。最新順・閲覧者数順・いいね順も確認する。
5. **ピン留め（`pins`）優先マージ検証**: 対象にあるピンの指定順と重複除外を維持し、残りを自動補充すること。存在不明のカードは合成しない。
6. **カード表示形式（`label=title` / `relative`）検証**: タイトルは末尾名または相対パス、フルパスは別欄で表示すること。
7. **アクティベート検証**: `window.pluginActivators['growi-plugin-portal-cards'].activate()` により View / Preview の両方に登録されること。

## 2. ローカルSandbox（`npm run dev`）
- `dev/sandbox.tsx`で、通常`http://127.0.0.1:5173/`にライブプレビューを表示する。ポート使用中はViteが選ぶ別URLを使う。
- 子ページ1件1カードで、パス・最終更新者画像・タイトル・足跡・抜粋を表示する。モックは一覧とID単位メタの2APIに分ける。
- 抜粋なし、60文字1行、120文字3行、240文字5行を選択欄とDSL編集で比較する。オフ時の高さ縮小を確認する。
- `/Engineering/Onboarding`は親なしの列挙元。`/Sandbox`は空本文・画像取得失敗の2件を表示し、メタ欠落のページはスキップする。`/Sandbox/ListError`は一覧失敗、`/MetaError`はメタ取得失敗、`/DeniedOnly`は正常0件。
- `/AccessCheck`を`limit=2, pins=/AccessCheck/Hidden`で列挙し、Hiddenのパス・タイトル・ピン表示がなく、ReadableA/ReadableBを補充して表示2件となることを確認する。

## 3. 新仕様の単体テスト

- 件数は行`limit`→行`shortcuts`→全体`limit`→全体`shortcuts`→12の優先順。`limit=0`は`count`設定を問わず全APIを省略する。`count=false`でもカードを表示するなら参照確認は省略しない。
- `excerpt`・`excerptLength`・`excerptLines`の既定値、全体・行継承、不正値、値域を確認する。
- 実際の7.1.9と同じ直接JSON、添字付きID配列、ID→メタマップを使う。無関係なIDは描画しない。
- パス・タイトル・画像・足跡・抜粋の実描画、空本文、欠落値、画像フォールバックを確認する。
- 抜粋オフはDOMと余白を省き、`attachShortBody`は送らない。足跡用メタは維持する。
- 文字数・行数だけの更新は再通信しない。オフ→オンは本文ありの取得を行う。
- Unicode結合文字を分断せず、省略記号込みで文字数上限を守る。HTMLは実行しない。
- 100件超からの上位12件と表示12件、対象のメタ取得、20ID単位の分割を検証する。正常な欠落IDは次候補で補充するため、参照不可が多い場合は表示上限以上のID確認を許容する。
- 同じ列挙元の通信共有、マウント破棄時の中断、無限補充しない欠落・バッチ403処理を確認する。
- 一覧途中失敗で不完全な順位・件数を表示しない。APIの必要フィールドが欠落した人気順も失敗として扱う。
- 参照不可の上位/ピン候補を除外し、パス・タイトルもDOMに出さない。抜粋オン/オフ両方で補充する。
- 全候補のメタが正常に欠落しても、各候補は一度だけ試行し、正常0件で終了する。通信失敗の警告を出さない。
- バッチ401/403/404/500・通信失敗・不正応答では未確認カードを表示しない。部分成功時は確認済みカードだけ残し、次候補の連続取得を止める。0件成功と取得失敗を区別する。
- 空ページは除外・補充し、空本文の参照可能ページは表示する。件数バッジが内部候補数を漏らさないことも確認する。

## 4. ビルド・ブラウザー確認

`npm test`、`npm run build`、`npm run verify:build`を成功させる。ルートエントリとv4マニフェストを維持し、distを再生成する。

Playwrightでデスクトップとモバイルの画像を確認し、横はみ出し、リンク、抜粋行数、オフ時の高さ、画像描画、ライブ編集を検証する。ブラウザーのズームを考慮し`innerWidth`でブレークポイントを判定する。

## 5. 実機で未検証の受入項目

GROWI 7.1.9へ実際に導入し、親なしのパス、View/Preview、日本語パス、複数ユーザーの足跡、グループ・非公開権限、100件超の一覧、標準の抜粋・画像との比較、サニタイズ環境でのカスタム要素描画を確認する。ローカル成功を実機対応保証とは扱わない。
